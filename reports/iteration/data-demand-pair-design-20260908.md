# 需求外数据准备：实际结果配对方案

2026-09-08，基于dev 1a3160a3。方案范围是同一分析目标下，省去纯粹为需求外数据而消耗的已知手牌；不是卡牌价值排序，不合入未通过的顺序/身份候选，不改变正式规则或物理转置身份。原型已成立，生产尚未实现。

## 已验证输入与方向

正式双路线均已填满计算机6格、恢复session为空。保留card-15-0的一侧余0数据，弃掉该牌的一侧余1数据。消去这张牌在各自手牌/弃牌堆的位置差异，以及该额外数据带来的焦点玩家数据实体差异后，其余完整已提交状态相同。其他弃牌的内容和顺序完整保留，不能排序整个弃牌堆。

首次原型错误地把保留牌追加到弃牌堆末尾，比较失败；失败及两套正式状态保存在data-demand-pair-prototype-20260908.json。修正的只读比较见data-demand-pair-comparison-20260908.json，不重跑正式输入。

真实第24步定点补采确认同样关系：物理节点12/18放数据完成后的两组来源，其rootAction/rootTarget/rootPlan、当前分析目标/计划、proxyDepth和信息遮蔽标志均相同，session均为空；差异另含每节点派生的反事实RNG。比较忽略该派生值后，其余状态关系成立。证据step24-data-pair-search-1501ebfd-20260908.json.gz及data-demand-pair-search-comparison-20260908.json。补采的4096节点、输入分类、规则失败和根动作与基线一致。

**这仍是用户指定的需求式取舍，不是严格全状态支配**：保留已知牌优于为当前分析目标增加无需求的数据。不更改实际RNG或让两条路线共用一次执行；不能复活身份规范化候选。原型没有生产副作用。

## 生产职责与闭包

| 边界 | 设计义务 |
|---|---|
| 唯一owner | rule-composition内部本次evaluate的来源调度；规则执行器、正式合法集、估值器不改 |
| 配对入口 | 仅已结算、session为空、同分析目标下实际填满第6格的准备结果；不在扫描尚未结算时推断产量 |
| 对照确实存在 | 两个结果都已真实执行，分别保存来源和状态证据；不以队列中可能成功的扫描当见证 |
| 根与目标义务 | rootAction、rootRouteTarget/Plan、当前目标、proxyDepth、信息边界必须匹配；不同目标来源独立判定，不跨根借代表 |
| 数据需求 | 双方均实际可继续分析；只能牺牲当前分析需求之外的数据，不能减少未填满的原需求 |
| 已知牌 | 唯一额外消耗的牌必须根时可见，且已真实进入弃牌堆；不使用盲抽牌面或拟合未来牌价值 |
| 完整状态 | 验证手牌/弃牌的精确单牌迁移、数据增量及实体布局；其他全局状态逐字段相同。任何额外钱电/收入/分数/科技/任务/外星人变化拒绝配对 |
| 身份边界 | 仅比较时消去已核验的版本号、焦点数据实体身份/序号和支持逐节点resetBranch时的派生RNG；不修改nodeKey、实际envelope、正式RNG或恢复输入 |
| 比较开销 | 只对上述分析准备结果建立局部候选表，不对所有节点复制状态、不引入全局缓存；先用资源/手牌差异排除不可能配对，再做完整比较 |
| 删除标识 | 记录多余结果的精确来源键与动作链前缀；仅筛除携带该来源前缀的后继，不影响共用物理节点上的其他来源 |
| 已排队后继 | 见证建立时及以后出队时都检查；无剩余来源才跳过物理执行。已执行节点不从统计中扣除 |
| 已保存结果 | 不能只清队列：addLeaf/addFrontierLeaf已经留下的多余来源结果也须在最终输出前过滤，否则旧结果仍参与评分/计划。保留同一物理结果的未删除来源 |
| 条件/控制 | 条件链不配对、不取消未结算正式输入；来源前缀可跨后续end_turn及奖励继承，但不改变正式控制动作 |
| 统计与报告 | 分别记录需求式取舍来源数、实际物理执行数、来源失效后的叶保留情况；执行历史不改写，已发生的预算截断原因不清零、不冒充搜索完整 |
| 失败 | 配对断言/回调异常显式传播，不能转为null或“不适用”吞错；契约明确不满足的状态才正常保留 |

## 验证与范围门禁

先在独立临时工作树实现完整来源生命周期，再集中验证；主目录保持dev。代码阅读必须覆盖mergeNode/出入队、addLeaf/addFrontierLeaf、最终outcomes及完成路线保留统计，不只改一个过滤点。

1. 使用上述真实状态正例；额外收益、不同来源、未知牌、未结算session、数据尚不足、其他弃牌变化均不得删除。原始root/envelope保持不变。
2. 两种到达顺序均要处理：多余路线先到时过滤已保存结果；代表先到时不继续排入多余后继。物理共享节点中其他来源仍正常执行。
3. 单点实际分类/节点和获胜计划检查，要求零异常且30秒内；对比新增比较耗时，不能只靠节点少外推提速。
4. 当前52后继不是承诺值：保留路线到达时，多余路线的12/13/14/15已执行，既有时序下剩余48个节点才有机会避免；不得回扣4个已执行节点。新的搜索时序可能重排，验收按真实来源/执行统计。
5. 单点通过后固定生产提交，经标准查重入口完整局一次，核对均分、执行/前沿截断与预期节点；未通过则独立归因，不直接叠加第五轮权重。

实现前仍需根据上述生产闭包读完各调用点，确认来源过滤不会遗漏已保存叶、计划或保留完成路线统计。该检查未完成前不得写生产patch。本方案不宣称已解决所有多来源组合或整个Goal。
