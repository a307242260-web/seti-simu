## 代码证据与尚未冻结的实现边界

`expected-score-evaluator.selectSecondaryAgentDataSettlement`已按来源共识选一次位置。
`rule-composition`在需求选位成功后立即break，保存原独立选择的分支随机种子；
只有旧的唯一computer排空路径会继续尝试下一place_data。下一次起手因此可能重新
排队、恢复fork和构造观察。优化应省这些真实工作，不能只把节点改为一组来计数。

生产patch前必须闭合：

| 义务 | 必需证据/边界 |
| --- | --- |
| 后继唯一 | 每个来源经正式后继选择器均只选同一place_data；若有并列打牌/目标完成/跨回合，不连续执行 |
| 状态和随机 | 对每个合并点保持原选位和下一起手的branchKey；逐边界完整envelope对比，不能仅比资源 |
| 奖励和信息 | 收入、精选、痕迹、科技及新信息屏障停止；不能跨奖励替用户选牌 |
| 来源推进 | 保留每个来源的完成状态、深度、绑定、信息标记及根即时观察；不能只依据动作名串相邻 |
| 计划 | 每个正式输入继续capture/retain；新计划逐步执行结果等于搜索所得状态 |
| 预算 | 4096/256/30秒不变；报告真实输入、fork/恢复次数与墙钟，不靠扩大每批工作冒充提速 |
| 验收 | 独立当前根单点、零实际失败、完整计划；再按标准唯一全盘比较111基线与108.5门槛 |

当前只有历史外层chain，不能看到节点内全部正式提交及对应中间盘面，尚不足以
冻结实现。下一步从现有完整冷搜索/计划证据确认132处对应状态与必要后继；证据
不足才补定向取证，不重跑旧全盘，不新增跨模块消费事件系统。

本轮无生产改动、无新模拟。已检查AI设计与数据融合设计，正式接口/规则未变，
README、AGENTS、RL契约无需更改；本文件是调查记录，不替代现行设计或验收结论。
