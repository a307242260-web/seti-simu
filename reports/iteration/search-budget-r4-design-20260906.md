## 方案取舍（建议，尚非生产口径）

1. 仅修完成度标记，保留全部旧截断：接口风险较小，但不能解决本轮要求的预算分配
   与目标裁剪问题，不作为第四轮完整交付。
2. 统一全局预算与显式有损队列选择，并分离结果可用性/完整性（推荐）：以现有
   Production fork和来源模型为基础；替换逐根停止叶计数，不重写规则执行。需要先
   证明去重正确性、明确预算内根覆盖和队列淘汰语义，再确定beam容量。不能把
   “调一个更高的leaf/node数字”包装成该方案。

时间门槛采用确定性节点预算下的单决策实测验收，不能仅根据机器快慢截断并改变
正常动作选择。是否需要生产wall-time硬保护及超时失败/恢复语义，须在冻结前决定；
若采用保护，应显式报错而非把时间耗尽结果伪装为完整搜索。

## 冻结前剩余问题与证据顺序

1. 核实忽略RNG/序号的合并是否有实际安全边界：正式下一步使用这些字段生成随机结果
   或实体ID，不能未经证明视为纯日志元数据。使用已有真实checkpoint验证，不跑整局。
2. 核实完成态支配的context是否包含未来可达性所需状态；若不足，需收紧同一搜索
   内的等价/支配契约，不扩展成全规则重构。
3. 在上述等价成立后确定全局node/beam预算、根覆盖与稳定排序，以及所有截断原因
   的累积方式；明确目标下界仅用于排序，哪些不可达条件能够安全剪枝。
4. 闭合结果消费矩阵：有完成叶且截断、无完成叶且截断、自然耗尽、规则失败、
   条件未完成、隐藏信息屏障、PASS边界。评估器/Policy/计划提取/诊断必须一致。
5. 设计冻结后集中实现。验证根状态不变、来源不丢、真实叶不丢、候选换序稳定、
   所有预算原因可追溯；白方已保存样本和棕方慢样本先通过10秒门槛，再提交干净版本，
   研究去重检查、固定盘面快速及同提交续跑完整局、版本登记与报告。

本轮不能以局部性能或分数上涨收口；仍要求实现符合设计，固定终局均分不低于
已通过基线106.75（相同则须逻辑更合理）。失败候选单独记录，不归因未证实的分差。

## 状态等价审查结论

`search-equivalence-r4-20260906-v2.json`基于真实棕方checkpoint，仅将下一火箭序号
由4改为104。两个状态均通过正式restore，根合法动作同为launch:c1616852，
正式提交后分别产生4号和104号火箭；向外移动分别为move:060dbf6f和move:6a43bbb0。
这不是两条已证明在同次搜索中可达的历史分支，不能据此归因固定盘面分差。
但它推翻了“序号不会影响正式后继”的一般假设；现有nodeKey归一化恰会忽略此差异。

设计决定：状态等价和资源支配context保留完整RNG与实体序号；不引入身份重命名/
映射机制。版本字段是否可忽略继续按动作版本和恢复边界核实，不把所有meta混为一类。
正式runWithWorkingState从state.meta恢复RNG并写回消耗后的状态；没有证明可以在
未来含随机行动的节点中忽略它，因此同样保留。此处属于搜索去重契约，不改正式RNG。

另只读此前全部goal-completed叶，按同根动作、目标深度和完整completionFacts分组，
未找到事实完全相同而火箭位置不同的叶对。该负结果只覆盖此存档，不证明
completionFacts包含全部未来状态：源码的valuationContext只含轮次、蓝槽、研究
机会和手牌，未含火箭位置、公共扇区等。完成态支配目前会阻止下一目标展开，故仍
须证明未来模拟关系，不能仅凭终点评分事实宣称无损。

首次诊断因脚本只改compositionEnvelope、未同步checkpoint.coreState的同一序列化
字段而被restore拒绝，失败记录保留为`search-equivalence-r4-20260906.json`；修正
脚本输入后另存v2。没有为该脚本错误修改生产验证器，也未覆盖失败证据。

## 完成事实与未来状态的非等价证据

`completion-state-r4-20260906.json`从同一真实棕方checkpoint正式发射4号火箭，
再分别执行向外、顺时针、逆时针移动及其正式支付。每例2次提交，条件选择明确
记录，未改输入状态、未运行AI搜索。三条路线的secondaryAgentCompletionFacts
完全相同，但火箭分别处于(4,2)/(5,1)/(3,1)。登陆火星所需能源分别为3/3/5，
移动步数分别为1/1/3；向外与顺时针两例的后继合法集也不同。

这直接说明该事实目录不是未来可达性的完整状态。样例结束于普通移动，不声称
它们恰好触发过同根同目标完成态支配；本盘误剪及终局分差因果仍未证明。
但retainCompletedEndpoint当前用这些事实判支配后直接continue，并淘汰后续frontier，
因此不能把它描述成已证明无损的未来搜索剪枝。

设计决定：不同完整未来状态不能仅因终点评分事实相同/较优而互相淘汰。
正式状态、session/Decision、RNG、实体序号和来源义务等价时才允许共享执行；
非等价状态的预算选择走显式有损队列规则并报告截断，不继续扩充一个猜测式
valuationContext字段清单来冒充完整状态。评分事实保留其估值职责，不拥有规则等价性。

下一步集中闭合全局队列容量/根覆盖及完整性消费者契约，不再重复上述已成立反例。

## 第四轮实现设计冻结

本节是当前实施口径，替代前文未决项。归属独立R4版本；不是R3验收通过，
不把尚未证实的历史误剪或终局分差作为修复成果。

### 搜索空间与预算

- 唯一执行owner仍为rule-composition，共享Production fork/inputPort；不建第二引擎。
- 节点去重使用完整envelope/session、动作及剩余条件深度的既有exactNodeKey。
  保留RNG、实体序号、版本，不做身份重命名。originKey继续保留不同根、目标/计划、
  深度与信息状态的后继义务。去重只节约物理执行，不吞掉后到来源。
- 删除次级搜索按资源摘要/完成评分事实的支配淘汰。不同未来状态交给有损预算
  选择，不声称“资源较多必能模拟资源较少”。删除对应无用私有helper/计数，公共
  估值函数若仍有实际消费者则保留，不横向清理无关模块。
- 次级搜索物理执行上限保持4096。队列保留上限为256个物理节点，容量必须至少
  容纳本次候选根动作数且不超过执行预算；输入不满足时显式参数错误，不偷偷放宽。
  256是首版明确的工程容量（4096/16），不是得分最优值；性能或效果不达标须分析，
  不以反复试数字代替设计。
- 根首步在后继之前执行，确保每个进入搜索的根都被尝试。之后每次合并一批后继，
  对合并后的完整队列做统一保留：按既有compareNodes排序，每个尚有frontier的
  根动作保留其最优一个物理节点，再由全局排序填满剩余容量。共享节点只占一格，
  其中全部origin一起保留；淘汰节点的全部origin归属各自根的截断记录。
  这是全局beam，不是逐根叶上限，也不保证每条根目标路线都展开到完成。
- 取消次级搜索maxLeaves饱和；普通control浅评估的原maxLeaves/maxNodes不变。
  已保存的真实goal-completed叶不随队列淘汰删除。frontier不作为收益叶/计划。
- 下一目标不再只留一个最便宜者；资源下界保留为目录排序依据，返回全部已准入
  目标绑定。取消未绑定后继top-4截断，交给全局beam。仍遵守已批准的“手段行动
  需要目标”、未绑定quick根不借后续主行动收益等策略边界，不恢复无目标交易枚举。
- 目标深度15、条件深度15和既有未绑定深度边界保留为显式范围截断，不能称为
  无损剪枝。正式目录和具体路线selector判断不可达的原逻辑不额外泛化；资源
  下界不能单独证明不可达，未来可取得资源时不得仅凭当前缺口删除路线。
- 不用wall-clock截断后选一个部分结果，避免机器负载改变正常策略。单次次级搜索
  使用10000ms期限，在宏步执行前后检查；超时显式抛COUNTERFACTUAL_SEARCH_TIMEOUT，
  清理隔离fork且不返回Policy动作、不推进真实根。不新增恢复/重试旁路。同步宏步
  不能被中途抢占，因此期限不是严格实时中断保证；超过10秒也不得继续完整局实验。
  节点内折叠提交沿用有限排空边界，executionStepCount与物理节点计数分开。

### 完整性与消费者矩阵

沿用outcome.status表达结果可用性，不新增一个会被现有评估器拒绝的incomplete
status。新增可选元数据searchCompleteness：`{status, reasons}`，status为complete、
incomplete或not-evaluated；reasons为去重排序后的字符串数组。它描述已声明的
单席目标策略搜索范围，不代表穷举真实多人游戏。旧外部v1输入未提供时不推断
complete；本生产输出和未评估补齐路径必须提供，提供时严格验证枚举及一致性。

| 执行情况 | 可用性/完整性 | 唯一owner及消费义务 |
|---|---|---|
| 有真实叶且beam/node/depth截断 | settled / incomplete | composition保留叶并记录原因；评估器/Policy仍可选，计划只取该真实优胜叶 |
| 无真实叶且截断 | unresolved / incomplete | 不生成替代收益，不从frontier提计划 |
| 声明范围内自然耗尽 | 有叶settled，无叶unresolved / complete | complete只表示范围穷尽，不等于该动作有收益或全游戏最优 |
| 正式执行或selector失败 | 原failed/部分结果状态 / incomplete、branch-failed | 保留原显式code/message，不包装成无损不可达；本轮不新增容错 |
| 条件输入未完成且深度停止 | 无该分支完成叶 / incomplete、conditional-depth | 不把支付中间态包装成已兑现目标；其他已完成叶仍保留 |
| 目标深度停止 | 保留实际完成叶 / incomplete、goal-depth | 不让深度上限冒充自然穷尽 |
| 未绑定范围停止 | 原有真实叶可用性 / incomplete、untargeted-depth | 明确归属对应根，不混记为节点耗尽 |
| 隐藏信息屏障及代表选择省略 | 现有遮蔽/叶规则不变 / incomplete及对应原因 | 标记近似，不读取隐藏信息、不改排空策略 |
| PASS/独立条件根的正式边界 | 原有边界叶保留 | 属声明搜索范围；若无其他截断可为complete，不模拟对手未来 |
| setup或目标门控未评估根 | unresolved / not-evaluated | completePolicyOutcomeSet补原因；不伪称因预算不足 |

原因至少覆盖node-budget、beam-budget、conditional-depth、goal-depth、untargeted-depth、
representative-choice、information-barrier、branch-failed、not-evaluated。删除的逐根叶计数、
首个最低价目标和top-4不再产生新统计。所有仍存在的有损选择必须归属到根；若原本
只在全局记数，直接在对应origin处累计，不新建跨模块全机制事件账本。

projectOutcomeObservations现有元数据复制透传该字段；assertOutcomeSet校验；Policy
与expected-score-evaluator仍依据真实叶评分，完整性不增加评分权重。plan-continuation
提取同一优胜叶，搜索不完整不能造成“已完成计划不可用”，也不能授权复用尚未执行
的frontier。Browser/Simulation共用此链，不增加Browser适配器或正式存档schema字段。
