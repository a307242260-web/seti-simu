# 资源准备缓存的动作身份隔离（局部修复通过，整体未通过）

## 已复现的问题与边界

`resource-cache-seat-order-20260907.json`通过只读源码在隔离VM中暴露现有纯函数，
不改函数体、生产模块或正式规则。输入资源来自真实棕方171：4信用点、1能量、
5宣传、4普通牌；动作编号分别来自棕方171与绿方42的正式交易descriptor。
保持交易种类集合相同，只改变动作编号排序，405个需求组合中25个缓存结果不同。
绿方descriptor用于控制变量，不代表绿方当时也持有同样资源，不能称为完整局复现。

真实棕方目标`launch:land:venus:planet:`的需求为2信用点、4能量，恰在反例内：
冷缓存返回cards-for-energy；先用绿方编号填缓存后，棕方返回credits-for-energy。
函数内部同成本/同终态代表依actionId排序选择，但缓存键只包含交易种类而无动作
身份，导致后调用者沿用先调用者的代表。不是跨席执行非法动作：返回时仍映射到
当前legalByTradeId；错误是候选集合依缓存历史变化。

这证明缓存遗漏排序依赖，不证明历史171/173搜索的5539/5542差异或终局-29全由它
造成。作为独立缺陷处理，不在移动改动摘要中混入。未调评分、路线偏好或预算。

## 完整修复边界与验证义务

唯一owner为expected-score-evaluator的selectMinimumCostResourcePreparation。
准备结果缓存键必须覆盖实际用于代表排序的tradeId/actionId映射；不能仅改成
tradeId排序（会改所有冷缓存决策），不能禁用缓存冒充完成，也不能加玩家特例。
resourceDistanceCache只缓存固定交易图上的距离/终态，不消费动作编号，保持不变。

| 边界 | 义务 |
|---|---|
| 同资源、需求及动作映射 | 冷热结果逐项相同，可继续命中 |
| 同交易种类、不同动作映射 | 不共享代表结果，各自等于自己的冷结果 |
| 输入顺序不同、映射相同 | 规范化键相同；不改变原actionId排序 |
| 动作authority更新 | 输出从当前legalByTradeId读取，不能返回旧descriptor |
| 重复交易首步 | 本轮不新增去重语义，不改变当前调用者的归并责任 |
| 来源/规则/计划 | 不修改状态、RNG/id/sequence、Decision owner、正式费用及提交链 |
| 消费闭包 | 探测准备、扫描、分析、科技与收入的资源准备调用共用此键，无第二缓存路径 |
| 失败与可选空结果 | 现有不可达返回空集合契约不改，不吞实际错误 |
| 性能与完整局 | 先真实单决策≤30秒、4096上限、节点与输入计数、优胜计划正式重放；再新版本唯一全盘 |

按用户标准在独立修复分支实施、验证、登记。需同步ai-design中资源准备缓存描述；
不改公共接口、浏览器脚本装配或Node测试分类。全盘分数目标仍≥109.5，失败候选
91.75不能成为新基线。修复前后必须区分冷启动一致性修复与整局分数因果。

## 与 scan-earth 版本的耗时差异（2026-09-07补记）

`scan-earth-r3s1-20260906`记录的145621ms只包含从第200步恢复到第529步的后段；
前200步另耗48918ms，因此可比的整局记录耗时为194539ms。当前版本从第0步运行604步，
耗时527641ms。步数只增加14.2%，主要差异不是局长，而是策略搜索工作量。

当前版本180次实际搜索共124980物理节点，搜索内部累计392142.78ms，占整局74.3%；
其中24次策略搜索跑满4096节点，累计302548.72ms，占整局57.3%。控制浅搜仅88节点、
940.34ms。R4此前删除逐根叶饱和、摘要支配、单目标调度和未绑定top-4后，更多目标与
路线进入4096节点全局预算，这是当前主要耗时来源；资源准备缓存修复自身相对前候选
节点减少6.84%、耗时减少0.45%，不是回退来源。

旧版历史采集器会把计划复用重复登记为最近一次搜索，不能从原记录直接得到精确节点
总数。行为不变的隔离诊断在同seed连续运行得到34759节点，约为当前版本的1/3.595；
但连续运行保留第200步计划，终局为534步，与原full从quick存档恢复并清空计划后的529步
轨迹不同，因此这里只作为“3—4万对12.5万”的量级证据，不宣称原历史轨迹的精确倍数。
完整口径和聚合值见`resource-cache-performance-attribution-20260907.json`。
