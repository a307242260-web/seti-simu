本项承接完整移动设计，不是新策略版本，也不是生产优化通过。输入沿用已验证的
148/497四条正式路线和检查点；不运行AI、不重复完整局。对应实现仅在adhoc中。

后续v5将队列提为routeToPurpose，支持位置满足集合与bonus两种目的，事件次序

## 查询契约与实现边界

| 项目 | 当前原型 |
|---|---|
| 指定目的 | 一个已注册有效bonus；来自当前working state，不读取未提交事务的committedState |
| 进度 | 直接复用describeEventBonusProgress；保留usedKeys/claimedKeys，不把返回原坐标当循环 |
| 奖励可用性 | 先在当前盘面可能产生的到达事件与move事件超集上查询；全无reward/progress时不建路线图，不自行推断onceKey |
| 几何和费用 | canMoveFromCoordinate、getRequiredMovePointsFromCoordinate；环边界属于rockets，不属于solar.layout |
| 阶段 | 当前card_move读取payload.remaining，首次才读取movementPoints；卡牌阶段只允许卡牌移动或结束，再用公司/付费手段 |
| 公司 | 显式区分未开启和正在选择；pending阶段不可插入付费移动；公司额度来自既有路线实验参数，不冒充正式启用可用性证明 |
| 状态键 | 坐标、剩余卡牌点、公司额度/阶段、访问/领取进度、完成状态、首步身份；不改正式状态或实体/RNG |
| 路线准则 | 最低付费点，再最少移动次数；保留所有同成本首步，不把这一成本准则当作沿途完整奖励支配 |
| 首步去重 | 相同首步只输出一次，不同剩余公司额度的后续路线保留为该首步的多个见证，不生成重复Action |
| 预算 | 几何查询超过4096状态显式拒绝；这不是Production搜索节点记账，Production4096/时间/beam均未改 |
| 完成/计划 | 本原型不生成Policy目标、origin或plan；后续接入仍须保留正式奖励Decision排空与主/次来源依赖 |

与此前只从空进度求一条路线不同，本项逐个真实阶段查询当前进度，并保留同成本
首步及其不同后继见证。支付Decision阶段不生成方向，继续由正式支付流程执行。
同一移动同时查询到达事件和move事件，不用visitPlanet覆盖同环move语义；本次
行为证据只覆盖b24/dlc12，不外推b125等所有模型已验证。

## 实验中暴露的问题（均未进入生产）

1. 初版在已领取dlc12奖励后继续求路线，正式规则仍允许记录其他新星球，但不能
   再领奖；这个无目标图耗尽4096状态。修正为先用共享规则查询有无可推进收益。
2. 第二版将环边界常量误读为solar.layout字段，undefined使事件遍历为空，被真实
   148“应可达”断言挡住。已改读唯一owner rockets，未加默认值或吞掉失败。
3. 第三版费用/阶段通过，但同首步的不同公司消耗终态重复输出，最终版按首步
   分组保留路径见证。前三份记录保留，不覆盖失败或把它们说成生产规则故障。
