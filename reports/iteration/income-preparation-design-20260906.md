# 收入准备转换：完整资源需求设计（2026-09-06）

## 证据与范围

实际绿方盘面收入路线为补2能量用完4张手牌，扫描后的第4格无法插收入。
`income-card-reserve-witness-20260906-v3.json`已通过正式输入证明：用3宣传精选1牌，
再两次换能，扫描后填第4格有合法收入Decision且正式收入轨增长。没有运行AI搜索。
v1失败是诊断把正式slotIndex误写为publicSlotIndex；v2失败是重复点击已选支付牌，
导致取消选择。两次均为诊断驱动错误，保留记录；未修改生产规则来适应脚本。

本方案仅修最小资源转换器对收入目标的终点资源要求。它不保证所有收入来源或所有
后续选择都能完成收入，不给任意扫描/卡牌加保牌禁令；直接可执行动作仍交正式搜索
评估。前述扫描依赖保持，收入评分、科技权重、搜索目标深度与全盘验收门槛不变。

## 设计矩阵（实施前按此核对）

| 边界 | 完整职责与证据 |
|---|---|
| 正式需求来源 | science-session的计算机4号位income奖励由手牌列表提供选择，至少需1张手牌；公开income data计划在nextCost声明handSize=1。nextCost是规划所需持有量，不是把手牌计入正式扫描扣费 |
| 唯一转换器 | selectMinimumCostResourcePreparation保留当前TRADE_ACTIONS、正损耗递归和非支配终态保留方式；satisfied增加手牌要求，不以中途手牌归零拒绝一条能补回牌的完整转换链 |
| 既有手牌模型 | 现有转换器只把ordinaryCards计为可支付容量，不趁本次扩大所有路线对外星牌的支付探索。收入可用所有手牌，因此普通牌保有下界为max(0, required.handSize-alienCards)；未建模为可支付的外星牌数量构成保守留存容量，具体弃牌身份仍由正式执行提供 |
| 缓存与状态等价 | preparationKey与resourceDistanceCache的stateKey都包含手牌目标，不能把“无需留牌”和“需留牌”当同一距离。状态仍为钱/电/宣传/可支付牌四元组，终态key不变 |
| 根与后继 | 收入data根准备、绑定收入路线后继准备均使用同一nextCost；无手牌要求的探测/分析等旧调用以0为默认，行为应等价。直接scan/place_data不因本次增加环境特例 |
| 搜索与预算 | 不新建状态空间、叶类型或第二套转换器；每个转换的四资源总数严格下降，递归有限，memo复用。外层global4096节点及原深度/叶限制不改；单决策10秒门槛保持，第四轮整体预算义务仍未完成 |
| 正式提交/隐藏信息 | 正式支付、精选、盲抽、扫描、收入Decision及RNG/id/sequence/session/recovery不改。转换模型只使用公开本人资源数量，不读未来牌身份；收入选择按正式手牌执行 |
| 排除项 | 不以新规则禁止中间耗尽手牌，不伪造收入收益；不修改卡牌估值、任意目标的资源价格、连填数据折叠或全部扫描来源依赖；不把某条路线可行等同于它必然最优 |

## 验证门禁

1. 同一实际状态：旧费用目标可以换光手牌；新收入费用目标返回的完整最小转换终态
   必须同时满足钱、电、收入牌要求，并能通过正式支付/收入链验证。
2. 同资源不同手牌需求的冷热缓存分别验证，不能交叉污染；无此需求的既有调用等价。
3. 有牌、无牌但能补牌、完全无补牌办法、有外星手牌、交易后才能补回牌分别核对；
   测目标行为，不检查私有函数名。根候选与后继候选都覆盖。
4. 单次真实绿方决策与慢棕方样本验证，超过10秒不得全盘。相关unit/V审计与指定
   两个既有失败分开记录；不为通过测试修改其他机制。
5. 实现和文档同提交，干净版本按标准去重快速→完整终局登记。第三轮仍以106.75
   为通过基线；这项独立修复与上一候选89.25也比较，不把局部通过当整轮通过。
