## 2. 全局冲突：完整性契约测试失败

三项配额加上"每条正式路线首个完成叶之前不设配额"的保守边界后（route 级 `routesWithCompletedLeaf`）：

- `randomizer/app/simulation-counterfactual-outcome.test.js` 仍失败：
  `至少一个正式结果目标根产生完整叶`（第 409 行）。
- 逐项隔离：`chain=12`、`entries=16`、`perTarget=4` **各自单独**都会让该断言失败。

原因：`markPruned` 会把 `outcomeState.pruned` 置真，于是该根动作的 outcome code 变成
`COUNTERFACTUAL_SEARCH_PRUNED`。配额一旦全局生效，**每个候选动作都会被标记为被剪枝**，
不再存在"干净跑完、code 为空"的根——而该断言要求至少存在一个。

## 3. 结论

1. 配额确实能把热点截断归零且不动决策（482 首次实测），但**全局代价不是"分数下降"这么简单**：
   它同时抹掉了"至少一个候选动作被完整搜索"的保证。
2. 不能通过改断言来通过（迭代规范禁止）；也不能把"全部根都标记 incomplete"当成零截断——
   那是把截断换成了全局低置信度。
3. 因此"零截断"不能靠静态全局配额达成，需要以下之一：
   - **动态配额（下一候选）**：搜索正常跑到接近预算（如 75%）仍未见收敛时才启用配额，
     这样小决策保持干净、只有爆炸决策被降级；需重新验证 409 行断言与 482 热点。
   - **可采纳上界 + 分支定界**：真正无损的收尾，研究性强。
   - **owner 修订契约**（接受"允许没有干净跑完的根"）或改验收口径。
4. 本轮不登记版本、不合回：失败候选与证据留在临时目录与 adhoc。
