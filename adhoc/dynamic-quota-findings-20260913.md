# 动态配额实验：执行截断 49→10、均分 103（仍 ≥100），队列 trim 依旧（2026-09-13）

临时目录 `/tmp/seti-zerotrunc-20260913.Mpk7bX`，起点 `8badab3e`。提交 `518877b2`。

## 设计

三项配额（宏步链长 12、每目标入口状态 16、目标级队列保留 4）**只在搜索执行节点超过
50% 预算（2048）仍未见收敛时启用**（`quotaArmAtNodes`）；另外每条正式路线
（根动作+根目标+根计划）产生首个 goal-completed 叶之前一律不设配额。
这样小决策保持"干净跑完"，只有真正爆炸的搜索被降级。

## 结果

| 指标 | 当前 dev（budget-clone-01） | 动态配额 |
|---|---|---|
| 步数 / 均分 | 578 / **113.5** | 600 / **103** |
| 执行截断搜索 | 49（战略 44 / 控制 5） | **10**（战略 4 / 控制 6） |
| 队列 trim 搜索 | 54 | 61 |
| 任一截断 | ~60 | 67 |
| 整局耗时 | 989s | **778s** |
| 最慢决策 | 19.1s | 17.0s |
| 全量测试 | 99/99 + 1/1 | 99/99 + 1/1（含此前失败的 completeness 断言） |

第 482 步臂长扫描（`adhoc/budget482-armsweep-20260913.json`）：arm≥2048 时执行截断即可归零，
决策与 13 步计划逐字不变，482 的队列 trim 从 1101 降到 221~711（arm=1024 时 221）。

## 结论

1. **动态配额可以大幅削减"执行预算耗尽"类截断（-80%）并把均分保持在 100 以上**，
   同时小决策保持干净（completeness 断言恢复通过）——这是相对静态配额的关键改进。
2. **队列 trim 无法用配额消除**：只要搜索仍然跑 best-first，队列就会超过 256 并被裁剪。
   要归零只有三条路：改遍历方式（活队列天然 ≤256，但改变搜索行为）、放大队列（等于扩大预算，被禁）、
   或 owner 修订验收口径。
3. 本候选**未合回**：它用 10.5 分换掉了 39 处执行截断，而目标是"均分≥100 且零截断"，
   两边都没同时满足；登记供决策，不计入已接受版本。
