# 展示外星人牌的公开信息与执行身份：下一学习项（2026-11-07）

这是调查与后续设计，尚未实现，不改变已冻结V277。

实际及7-input控制的第157选择都是`amiba:display:9`。必须看该上下文的完整Native target，不能凭actionId推断盲抽。第177实际打出阿米巴9，新增探测器并通过橙符号得4分。两张opaque槽是搜索表示：其中阿米巴9由展示选择获得，另一张为新抽牌；不是“两张都盲抽”的证据。原生记录/校验正确，先前按ID解释来源不准确。

已经定位两个不同问题：

- 浏览器`randomizer/app.js:350`读取已揭示物种的displayedCardIndex，并在373附近渲染展示牌图片；`amiba.getPublicTraceState`（amiba.js:534附近）只向标准观察提供displayedCardAvailable和blindCardCount，未提供公开展示编号。root156观察确无编号，157合法菜单才明确display9。
- AnalysisPort只按根时已有Native实例ID保留卡身份。展示外星牌直到领取才创建新Native实例；即使其公开模型已知，领取后也被当匿名。禁止伪造root实例ID；不能按实际盲牌结果扩充根知识。

建议先完成正式公共信息契约：仅在阿米巴已揭示且展示确有牌时发布模型编号/卡模型ID，不暴露牌堆；未知物种仍null。Browser、Simulation、factsFromState/fromObservation用同一只读模块。UI已公开与观察新增字段必须有明确一致性证据。

随后局部扩展搜索节点的知识归属，推荐每节点记录“通过根已知展示选择取得的真实Native实例ID”，而不是修改整个端口的根ID集合或伪造Native实体：

1. openRoot冻结根已知公开展示模型；只在实际Native sourceAction选择该根已知展示模型时，按前后自有手牌差额证明真实新ID及模型一致，才将该ID加入此子节点知识。盲抽及领取后新补出的展示牌不得升级为根知识。
2. 知识随同一节点的resource/movement视图传递，与Native state/Session/RNG分开；既有Root-ID路径零额外知识时保留快路径。不同知识上下文必须进入policy identity/cache key，planningState按[state,knowledge]缓存，不能把同Native状态不同可见信息合并。
3. 已知ID用于完整/紧凑估值、过滤合法动作、已知收入/角标及必要贪心计划；不全局污染兄弟分支的blind选择，也不读取未知新牌模型。Native真实输出不改。
4. 先复现展示9被mask，再用严格Native已知领取/未知盲取对照、隐藏牌堆置换、兄弟分支反向展开顺序、冷恢复、观察全/紧凑一致、根/RNG隔离验证。保留实际root156/157，单点预算仍256Native/600ms、生产全局预算null。
5. 若要按“当前Native全状态＋根公开模型唯一性”直接推导可见ID，须额外证明公开牌不会从隐藏堆获得、没有回堆/复制/其他owner同回合干预。该路径较少改节点结构，但更依赖物种规则；不能未经证明仅按cardId匹配就泄露blind结果。因此优先采用具体已知领取的局部节点知识。

公开身份保留之后，还需单独核查持有阿米巴9的下个主行动用途是否进入V48；现有held-symbol资本只支持特定效果，不代表所有公开牌都有未来价值。不能把补字段自动当作估值已经完整，更不能因为教师本局盲抽A7就把免费选牌固定改为blind。选择应基于当前已知用途，必要时另建基于公开剩余组成的明确期望，而不是偷看种子。
