# AI 高节点搜索性能迭代（2026-09-06，用户批准的新 Goal）

目标：找高节点搜索，按节点类型与具体选择统计，依次消除不必要的搜索，直到继续减少
节点难以带来显著实际提速。当前生产基线213f34db，固定免电分析盘面702步、均108.5，
quick加续跑527450ms。上一轮四轮实现已收口，不重开或改写其历史失败记录。

## 顺序与门禁

1. 复用已有统计；补取当前存档四席首个高节点边界24/42/49/52的单次冷决策，另复用
   绿方210步已有完整统计。正式重放前缀、保存输入与结果，不重跑完整局。冷决策可能
   不同于历史缓存复用，必须记录是否与存档动作一致，不将其当作历史缓存日志。
2. 分开统计物理节点family、具体选择、origin所属目标及实际耗时。origin可共享节点，
   不能混加；347条budgetHits可能重复携带旧诊断，不能当作347次独立搜索。
3. 优先检查占比大的choose_target中哪些只是需求确定的结算。当前缺口假设是：
   selector已选出唯一数据位置，而executeNode仅认识合法集原本唯一的computer选位，
   导致确定性结算仍回到队列；必须以正式描述符、目标上下文和实际执行证明。
4. 每项生产改动前冻结完整边界：唯一需求判定owner、每origin目标/来源、状态等价、
   资源下界、全局4096节点/256队列/30秒期限、正式提交与奖励/揭示/停止边界，以及
   actionChain/计划/计数消费者。不因为多种奖励名字相近就视作等价；不强制computer，
   不另建协调器执行器，不以降低预算或只改节点记账制造提速。
5. 单决策先验实现正确与实耗改善，再中文提交、研究去重、版本化quick→full。固定
   盘面终局均分须至少108.5；不符合预期找实现原因，独立缺陷单独修复，不能调权重
   追分。沿用迭代中心§2.1，摘要只写改动。每项完成报告，指定两项旧失败不处理。

## 停止判断

不以“低于4096”或某次耗时下降直接收口。对优化后的代表性高节点状态重新排名，
结合单节点耗时、必须保留的真实选择与重复开销判断剩余收益。优先处理预期能减少
约10%单决策耗时的项；低于该量级不机械禁止，但需解释实际收益与实现风险。
当大头已是必须保留的真实分支，剩余可安全省掉的节点估计仅有小幅收益，且实测
瓶颈转到规则执行/投影等其他成本时，记录停止依据与未覆盖状态，再结束Goal。
这是本轮工程筛选尺度，不是新增游戏策略或用户要求的固定性能数值。
