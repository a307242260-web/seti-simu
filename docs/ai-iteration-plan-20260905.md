### 已核对的奖励执行闭包

- 数据放置唯一正式 owner 是 `effects/science-session.js` 的 PLACE_DATA；复用
  `abilities.executeAbility("placeData")`，取得正式 `slotBonuses`。
- blue1/blue2/blue4 经 `appendResourceBonus` → `players.gainResources`；宣传有上限，
  事件里的名义 gain 不能未经核对当作实际到手量。blue3 会派生 PICK_CARD Decision，
  不是放置时立即拿到牌；不能只数 placeData 事件便认定选牌奖励已完成。
- 计算机列2分同样从这条链结算，但已在正式分差中，不得再次作为蓝槽资源奖励。
- `rule-composition.js` 的提交返回包含 session journal；既有 session 的每次提交返回
  的是累计 journal，归因若消费它必须按事件身份去重，不能在每个 conditional 重复累计。
- 搜索不仅有显式节点提交，还有 drain 的结算提交和连续 place_data 提交；任何来源收集
  都必须覆盖这些路径。共享状态去重、origin 分叉、隐藏信息屏障、失败/撤销和 checkpoint
  恢复都要纳入设计，不能只给最终叶新增一个缺省为0的字段。

### 第二轮宣传研究批次设计冻结

用状态预期差取代一次性门槛奖励：`P = 0.5 × max(可研究科技的未来价值 ×
min(当前宣传/该科技正式宣传成本, 1))`，宣传增量项为`P(叶)-P(根)`，不截掉负值。
只预估当前最好的一项研究机会，不把同一库存同时许给多块科技；研究兑现后，该科技退出
可研究集合、已支付宣传不再保留相同预期。通过差分保证同一轮内“攒宣传→研究”的预期
可合并、可扣回，不随拆成几个动作重复奖励。0.5沿用项目未来用途折半约定。

| 边界 | 唯一owner/正式输入 | 义务与行为证据 |
|---|---|---|
| 候选与费用 | Production `buildTechGainRequirements` 的正式plans/required.publicity | 不复制科技合法性或收费规则；候选缺失、耗尽、已拥有或免费研究均不产生宣传价值 |
| 完整/轻量输入 | outcome-model派生同一researchOptions（tileId/publicityCost） | 标准projection与strategicFacts逐项一致；保持viewer隔离；不携带执行器/隐藏牌 |
| 科技未来价值 | expected-score-evaluator提取既有科技未来价值纯函数 | 宣传不再有另一套固定60估值；与取得同块科技的未来估值同源；蓝槽公式的后续修正自动共用 |
| 最终叶/搜索排序 | leafValue消费P差分 | 0→5也可推进具体研究，但无候选时0→6仍为0；宣传超过单次费用不继续加值；支出/候选失效允许负差 |
| 研究兑现 | 正式ownedTech与剩余候选/宣传 | 拆成A→B→C与直接A→C的宣传项相同；不能保留已支付宣传的预期再全额叠加取得科技 |
| V/终局 | V增加researchOptionValue分项；terminal入口仍清空未来项 | V使用同一P；终局正式分唯一，R4没有未来科技窗口时P=0，不虚构不可见的背面奖励 |
| 状态/事务/RNG | 只新增viewer-safe派生事实，无生产状态写入 | 不改变Decision、执行/撤销、随机数、id、恢复或搜索目录；所有分支仍读正式规则观察 |
