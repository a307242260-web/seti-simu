# SETI 架构迁移与 Agent 执行复盘（2026-07-28）

## 结论

这轮工作的主要问题不是实现速度，而是长期缺少有限、可证伪的完成条件。大量代码被持续搬运，局部测试也不断通过，但最重要的端到端主链、旧入口删除和全仓残留没有同时记账，导致高代码吞吐、低目标收敛。

后半程在改用“完整设计矩阵 → 按 owner 批量实现 → 集中验证 → 物理删除旧路径”后，推进速度和稳定性明显改善。这个模式应保留；逐个 handler 修改、逐次跑测并从失败猜下一处的模式应废止。

## 经验教训

### 1. 架构迁移必须同时维护两套账

- 新架构账：唯一 owner、调用方向、公共执行端口、状态提交、恢复和宿主边界是否成立。
- 老架构账：旧 facade、registry、fallback、状态根、公共入口和兼容设施是否物理删除。

新模块存在、入口文件变小、测试全绿、某条竖切片成功，都不能单独证明迁移完成。整体完成只能基于固定提交的全仓审计；没有全仓残留基线时，不应给整体完成百分比。

### 2. 复杂迁移不能用测试发现设计

此前多次出现“改少量代码 → 跑测试 → 从失败发现下一处 → 小提交 → 再来一轮”。这会反复支付上下文读取、验证和提交成本，还会在根契约未闭合时持续扩大修改面。

正确做法是在首个生产 patch 前完成有限设计矩阵，至少覆盖：

- 语义来源与完整执行闭包；
- 唯一 owner、状态、RNG、id、sequence；
- Decision owner、stale/late/wrong-owner；
- 事务与不可逆边界；
- 新 primitive；
- 旧入口及其删除证据；
- 行为证据。

矩阵有遗漏时应停止实现并整体补齐，不应用兼容层或默认分支吞掉遗漏。

### 3. 测试不是天然正确的需求来源

迁移期间存在只服务旧结构、旧命名、旧宿主或伪策略路径的测试。若不先判断测试所证明的行为是否仍属于当前契约，agent 会为了让过期测试变绿而重新引入兼容层，甚至偏离新架构。

处理失败测试前应先分类：

- 当前业务行为：保留，并让新路径通过；
- 迁移期 characterization：在 parity 完成前保留，之后按契约删除或改写；
- 旧结构实现细节：删除，不驱动生产实现；
- 名义上验证产品、实际绕开产品行为的伪 smoke：删除或改名为窄契约测试。

### 4. 不能把代理指标当成架构目标

`app.js` 行数、文件数、提交数、通过的测试数和已迁出的函数数只能用于定位风险，不能作为主要完成指标。真正要看的是 owner 是否唯一、旧路径是否归零、Browser/Simulation 是否经过同一端口，以及行为是否从正式路径成立。

### 5. 全仓审计不能被推迟到最后

此前的 issue 拆分多次只覆盖目标 owner，没有完整覆盖来源侧的 generic facade、公共 API、字符串 registry 和根事务。最终审计因此第一次发现成片残留，又变成一轮新的大型实现。

复杂父子迁移在拆单前必须完成 source/target 双轴 inventory，并让每个旧入口唯一归属一个实现项。最终审计只做组合复核；若首次发现同类成片残留，应判定拆分失败并重新规划。

### 6. 搜索算法必须先做复杂度设计

启发式搜索初版直接扩大 DFS 深度，但没有共享搜索树、等价状态去重、目标约束剪枝和全局节点预算。`maxLeaves` 只是截断，不是 beam，也不能阻止每个根候选重复展开相同子树。结果是单次固定盘面决策达到约 179 秒，完整局报告无法完成。

正确顺序是：

1. 先定义终极目标、合法中间步骤和自然终止条件；
2. 估算分支因子、深度和节点预算；
3. 建立状态指纹与 transposition cache，禁止重复搜索等价子树；
4. 用资源下界、目标可达性和支配关系剪枝；
5. 使用全局 beam/node/time budget，而不是给每个根候选各自一份叶子上限；
6. 先测单次决策的节点数和耗时，再运行完整局。

### 7. 批量验证的频率应跟风险走

简单纯函数可以频繁跑定向测试；跨宿主、恢复、完整局和浏览器 smoke 应在完整语义批次后运行。每迁一两个函数就跑全量，会把机器和时间消耗在重复证明同一事实上；但完全不做阶段验证也会放大错误。验证单位应是“完整语义批次”，不是“改了几行”。

## 对 AGENTS.md 的处理

### 已有规则，不重复增加

- 复杂实现先冻结完整设计；
- 设计矩阵覆盖完整执行闭包；
- 按 owner/事务语义批量实现；
- 发现根契约遗漏时回到设计阶段；
- 性能问题先定位再优化。

### 本轮应新增

1. **测试契约审查**：迁移中修失败测试前，先确认它描述的是当前必要行为；旧结构测试不得驱动兼容实现。
2. **架构迁移双轴完成判据**：必须同时证明新路径成立和旧路径全仓归零；固定提交前不得用局部里程碑外推整体完成。
3. **搜索算法复杂度前置**：实现前明确状态去重、剪枝、全局预算和单步性能门槛；深度/叶子上限不能冒充剪枝或 beam。

这三条是现有全局规则的真实缺口，已进入 harness-evolve 晋升记录。其余问题主要是已有规则未执行，不再继续堆叠重复 prompt。
