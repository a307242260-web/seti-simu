# 搜索计算余量与固定计划续用（2026-10-29）

本轮先完成四项优化、复测冷启动节点，再按标准入口尝试一局完整搜索对局。搜索升级为v38；全局预算保持256次原生输入、257状态、256前沿、600ms。失败仍无可提交动作，不能把计划中未执行的步骤当作免费输入或已完成搜索。

## 范围、身份与状态归属

1. 已闭合窗口的最佳资源宏保留最多32个真实输入前缀。正式执行仍一次只提交一个输入并独立记入回放；后续可匹配此前实际模拟的同一前缀，不重复搜索准备过程。不同目标仍分别比较，只共享相同原生前缀。必要的身份敏感付款和不同科技类型继续展开，资源下界、全局预算及其他玩家/终局/信息边界不变。
2. 观察缓存按不可变原生envelope对象和遮蔽边界对象分别索引；完整字段保留。资源需求按不可变原生state对象索引，目标目录另外绑定完整合法动作信封。V的数值缓存仅限单次搜索和同一只读观察对象，模型资格仍检查原评估器。不按玩家资源摘要合并状态。命中率低时如实记零，不把缓存能力当成已经产生的提速。
3. 已提交状态解码使用精确字节LRU，最多64条，同时限制键的UTF-16大小总计8MiB。此大小是序列化键的占用门槛，不是JavaScript总堆上界。完整状态规范化另按不可变源对象和Session前缀/待处理引用编号映射缓存；保持原完整身份字节，先规范化pending、后state的顺序不变。每份结果完整冻结；Session工作副本仍独立，关闭端口清空全部计算缓存。
4. 主行动前收入、卡牌免费研究、公司增加收入来源进入明确目的计划。已知付款、插收入、蓝槽等沿现有贪心规则执行。不同科技类型、公司无效科技和未证明等价的原生选择仍在同一目的内搜索；普通宣传研究、蓝数据、卡牌研究及公司收入途径没有互相冒充。没有强制所有主行动前先插收入。

计划证据由搜索端口拥有。算法只持opaque token；对外trace不携带恢复胶囊、完整状态键或隐藏世界。可序列化的恢复证据放在宿主checkpoint/browser-save的可选`machineAI`旁车中，不写入规则状态、队列或RNG，不参与游戏等价身份。Browser、Simulation经同一agent-runtime导出和恢复。读档重新创建token，逐步核对完整规则/队列/RNG身份、合法信封和完整模型/策略配置；原目标已通过该计划证据绑定，不能把“下一步仍合法”当成命中依据。

模型变化忽略旧证据并重新搜索；状态、公开信息、RNG或合法集变化不匹配即重新搜索；损坏胶囊显式失败。没有旁车的旧存档仍从真实边界重新搜索，不能凭空恢复旧目标。生命周期invalidate/reset/new-game清理旧实例，显式恢复旁车在规则恢复成功之后进行。普通Browser恢复检查点仍可通过无旁车冷算恢复规则行为。

## 验证与实验顺序

先验证逐输入续用、JSON序列化冷恢复、Browser/Simulation一致、依赖失效、原生根与兄弟分支隔离，以及所有预算失败均不提交。再运行完整Node、Browser smoke和估值输入检查，最后以最终运行时代码执行八个固定冷根。只在单决策门槛通过后，通过`robot_iterate.js run --full --config agentType=search,activePlayerCount=4,compactReplay=true`执行一次固定世界对局。

完整局必须真实到达终局才能报告正式分数。180秒按标准runner从reset前至终局观察的`wallMs`验收，报告构建开销单列；中途失败保留搜索证据和正式存档，只登记为未完成尝试。

最新八点检查点为`reports/ai-foundation-20261023/search-buffer-corpus-20261029-v3.json`：8/8，第三轮493.4ms，第四轮553.2ms，余量106.6/46.8ms。八点动作及V与昨晚一致。前两次结果和源码变体保留，不选择性丢弃接近600ms的结果；单次样本与JIT/宿主波动不能解释为稳定提速比例。

最终完整Node回归前的Browser全组尝试在旧`production-browser-full-parity`项出现CDP `Runtime.evaluate`超时；其前五项已通过。随后按本轮范围执行并通过11项相关Chrome检查。历史估值装配`decisionObs`仍有aomomo冻结对象写入错误，不能宣称整份V审计通过，独立搜索估值输入检查单列。
