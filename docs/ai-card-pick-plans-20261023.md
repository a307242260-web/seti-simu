# 有目的取牌与固定选牌（2026-10-23）

搜索 v32 的生产玩家开启 `cardPickPlanning`。取牌先说明用途，再固定牌和支付；
“拿哪张牌”不再形成搜索分支。Browser 与 Simulation 共用同一实现。
这属于用户确认的策略范围调整，排除项标 `isEquivalence:false`，不冒充原生动作等价。

## 哪些情况才生成付费取牌计划

| 诉求 | 当前生成条件 |
| --- | --- |
| 缺一张牌插收入 | 当前持有数据足够填到计算机第四格，但没有可用的多余手牌；仅剩一张可支付主行动牌时保护该牌 |
| 缺一个关键移动点 | 一个明确的原生行星目标只差一点移动能力，取得已知移动角标牌后可达，并保留终点费用 |
| 缺一个关键数据 | 当前 turn 的分析目标只差一个数据角标，取得已知牌后能补到六格且留有分析费用 |
| 已知直接收益明显更好 | 只识别无条件直接得分净值高于现有手牌及取得成本的狭窄情况；复杂条件强牌尚不取得该权限 |
| 宣传没有科技用途 | 没有可取得科技、本席保留区没有剩余宣传计分、手牌少于四张；只允许使用宣传支付 |

没有诉求就排除全部付费取牌入口。支付来自当前真实合法动作，选择一条固定资金来源，
按现有线性刻度比较取得成本，并核对目标所需资源；两张牌付款选择固定实体集合。
付款和牌的选择是明确策略，不是全部支付方案同值的证明。
移动和数据诉求只接受当前公开牌能提供的确定角色，不把盲抽当作必定补到所需角标。

已经由真实玩家或上游计划付过费用的取牌必须完成，记录 `committed-pick`；
免费精选是现有目标的奖励，记录其明确用途或 `free-reward`，不会再制造新的付费取牌动机。
“选一张收入牌”“扫描牌对应哪个扇区”和开局选择仍分别属于收入、扫描与开局，未混成普通精选。

## 固定执行与选牌缓存

`card-pick-planning.js` 决定用途、牌、费用来源和付款实体。语义缓存最多 64 项，键包含：
已知候选牌的完整用途事实、诉求类型、所缺点数、固定目标牌（如有）及轮次。
支付顺序、钱包余额、Decision 版本和动作信封版本不进入选牌排序键。
同一诉求及同一牌面直接复用选中的牌身份，再绑定当前正式合法 descriptor；
候选牌或诉求变化则重新排序。隐藏牌堆身份与顺序不参与决策。

Analysis Port 在固定链中逐次执行原生输入，Decision Search 将中间付款/领取步骤压入计划边，
保留 `fixedChoices` 和所有 `steps`，不为每张候选牌创建搜索后继。
原生选择界面和 replay 仍保留：每次真实机器推进只提交一个输入、增加一个 replay 事件。
旧的数值同值归约不得覆盖计划指定牌，已有独立反例约束这一点。

缓存只复用“拿哪张牌”的结论，不复用另一状态的收益或完整搜索结论。
本席端口 close 后保留有上限的牌面缓存；reset/restore/invalidate 重建算法与端口，清空临时证据。
原生 Session 的起始状态可重建已承诺的取牌用途、目标牌和付款集合，这些信息另进入搜索控制身份；
完整规则状态身份不放宽，跨实体、不同用途、不同原生信封不能靠相似摘要续用计划。

原有全局 256 输入、257 状态、256 前沿、600ms 诊断预算继续生效。
每个固定输入前都检查剩余额度和时间；宏内部状态也计入全局状态/前沿。
中断返回未完成原因、实际已模拟输入数，动作和证书均为空。

## 证据

原始 062 的一条实际重放路径是：1 宣传 → 放数据第二格获得 1 宣传 → 弃牌角标获得 1 宣传 →
3 宣传精选。全程仍在第 2 轮、第 2 turn。旧报告的 284 次是不同假设状态上的动作展开累计，
不是一条 turn 路线上做了 284 次交易。
[原生路径](../reports/ai-foundation-20261023/publicity-trade-witness-v1.json)保留了每一步的资源与身份。

[固定领取基准](../reports/ai-foundation-20261023/fixed-card-pick-benchmark-v1.json)：
已付费的两张牌付款加领取共 4 次原生输入，2 个图节点、3 个内部证据状态；
冷启动含开根约 30.17ms。同一牌面、同一诉求再次冷算后缀，排序新增 0 张牌、缓存未命中新增 0 次，
仍逐次计入 4 个原生输入；它与整条计划 token 的零模拟续用是两种不同复用。
两次选中的牌、动作、V 一致，权威根状态不变。该基准不是完整游戏成绩。

行为测试覆盖无诉求排除、收入/移动/数据与科技耗尽条件、宣传计分保护、固定牌、钱包/版本变化缓存命中、
牌面/诉求变化失效、隐藏牌堆替换不变、旧归约不得改牌、宏中间的 node/frontier/input/time 中断，
以及共享 Simulation 的四个真实付款/领取输入与恢复冷算一致。

[八点诊断](../reports/ai-foundation-20261023/card-pick-plans-corpus-v1.json)仍为 5/8：
001/003/008/011/009 闭合，008 为 234 次模拟、含开根约 520ms；062/105/152 均超时，
分别实际使用 203/149/216 次模拟。比较范围已增加固定取牌策略，不把不同范围当成原生全树同值证明。

最终源码完整 Node 回归通过 **139 unit + 1 fullFlow**，五项真实 Chrome 检查通过。
固定选牌新增标准估值输入及所有原生前缀通过；共 32 条 independent 输入路径通过。
旧 decisionObs 的 `aomomo` 只读对象错误仍 FAIL，未将整个旧审计计作通过。

## 当前边界

现有 V 主要按手牌张数计值，综合牌力、条件牌和长期强牌的识别尚未完成；
这里的严格直接得分条件不能声称覆盖目录里的所有强牌。主行动前数据、兑换、科技与其他计划组合
仍可能超预算。本次未接入被放弃的队列顺序、取牌启动前数值界或历史事件上界原型。
信息/owner 停止边界沿用原契约；目标后续使用新取得已知牌并跨过无关补牌屏障的完整 turn 规划仍未完成。
没有新搜索完整局、终局分数或 180 秒验收。
