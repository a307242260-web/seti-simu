## 开发顺序与验收

1. 冻结v41完整局参照：同世界、同配置、标准入口，只运行一次，完整终局才给正式分数。
2. 对教师轨迹做可见事实与当前候选覆盖检查，区分“根本没有该目的”和“有目的但估值低”。先研究科技的持续收益、扫描—数据—分析—外星链、终局标记的增长；资源末轮持有价值单独测试。
3. 一次只改一类判断，先用真实冷根和不变性测试，再做标准整局对照。固定世界成绩改善和180秒同时满足才保留；不以模仿教师动作比例代替最终成绩。
4. 必要分支沿原状态身份、RNG、目标控制与资源下界完整探索；固定步骤、复用命中和真实分叉分开统计。不同候选的共享准备只模拟一次，不通过漏记成本提速。

价值学习只能读取当时可见的公开事实与本席手牌，不使用示范后续牌序/隐藏物种身份作为决策特征。历史得分可作为离线结果标签，不能由此给运行时端口读取隐藏世界权限。

## 首次完整局参照发现的问题

精确v41运行时（代码已核对冻结哈希）通过标准入口尝试整局，第321个已确认输入后，在蓝席第322步的搜索后继中抛出`Cannot read properties of null (reading 'scanCost')`。耗时24.484秒止于失败，**不是完整局耗时，未获得终局分数**。现场、已确认trace、存档和标准失败记录保留，登记为非baseline候选，原记录不覆盖。

根因已经用真实现场先复现：最后一席PASS后，正式状态`turn.gameEnded=true`，但Composition仍可枚举到残留控制输入。分析端口只按“合法集为空”识别terminal，误把该后继当stable并调用已不适用的资源需求目录，获得null。没有通过给scanCost填默认值掩盖终局。

搜索v42修正：没有未完成强制Decision时，以正式gameEnded事实关闭终局窗口、清空搜索后继，并读取正式终局评分。若原生Session仍在等待必需输入，继续执行该Decision。已有其他owner、信息及单turn边界不变。只修分析边界，不改正式游戏规则、估值、目标策略或额度。

真实故障根修复后194次模拟、约455.8ms，完整闭合并包含3个终局叶；原根与RNG不变。原10个冷根动作/V保持，另复验第317步。完整145项unit+1项fullFlow、3项相关Chrome通过。随后以冻结的v42代码另开独立实验，结果见下节；v41失败记录保持原样。

## 第一轮学习迭代：补齐固定换牌规划

教学样本暴露了现有规划器漏掉的公司换牌入口：公共菜单缺少`source/pick`字段，换出手牌也被当作搜索分支。先复现失败测试，再分两步处理：

1. v43：只将已经承诺的深空换牌公共菜单接入现有固定选牌规划，按相同牌面和相同目的复用排序。公司的收入／角标奖励菜单仍需要独立的目的契约，不按普通选牌混用。
2. v44：换出手牌按已知卡价、剩余轮收入及移动／数据角标用途贪心选择一张。该动作仍逐步走正式输入，不在树外偷偷结算。公共菜单仍按原规划器确定换入牌。

上一轮完成的是搜索成本收敛，不能据此推断策略变强。本轮先列出需要学习的判断，再按单项假设推进。
