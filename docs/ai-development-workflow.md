# SETI AI 开发流程

设计日期：2026-10-22。目标是建立一套可独立替换算法、稳定复现决策、比较完整终局效果的开发流程。
当前接口依据见 [接口清单](ai-interface-inventory-20261022.md)。本文定义新的开发主线；旧 AI 的待办、
历史成绩和阶段门槛不作为启动条件。现有规则、存档和输入契约继续有效。

首个交付目标是一个覆盖全部决策阶段、能合法结束对局、每步可解释和可重放的基础 AI。
随后分别建设估值、有限预算搜索、对局评测，最后按收益决定是否增加计划复用和学习策略。
本次只交付接口整理与设计，以下新 API、评测协议和性能数字均为待实现方案。

## 一 采用的技术路线

优先采用纯 JavaScript 决策函数和有限预算搜索，Browser 与 Simulation 装配同一实现。
这样可以先把规则接入、决策质量和计算成本分别量清楚。
另一条路线是直接训练策略或价值网络，但需要先建立可靠采样、冻结评测和模型推理接口；
放在本流程后期，避免用训练掩盖输入或执行问题。

```text
正式规则 → 席位观察与合法动作 → 共享协调器 → 新 AI 决策函数
                                                │
                          候选排序 → 搜索 → 叶估值
                                      │
                          可信分支服务 → 正式规则隔离分支
                                                │
                                返回 actionId → 协调器正式提交
                                                │
                               replay / checkpoint / 决策诊断
```

AI 只拥有选择。正式合法性、资源扣除、结算、条件 Decision、终局计分归规则；
恢复、执行和记录归宿主。候选排序、搜索调度和估值分别有可替换入口，初期用普通函数实现。

## 二 新 AI 的接入契约

### 决策函数

保留协调器已有的同步最小签名，不先引入新一套 Policy 信封：

```js
// 新 factory 的拟定形状，尚未实现。
const agent = createAgent({ config, analysisPort, onDecision });
coordinator.registerSeat(seatId, agent.decide);

// boundary 来自共享协调器。
function decide({ seatId, observation, legalActions, phase, sessionDecision }) {
  return { actionId }; // 必须命中本次 legalActions
}
```

初版只返回 actionId，不返回计划；新 AI 不读取旧计划缓存。
策略只消费已冻结的席位观察与合法 descriptor。sessionDecision 的完整 runtime 对象留在可信边界，
进入算法的数据只取已确认公开的结构化 Decision 信息；不能把整个 session 传进模型。
同一算法版本、输入和策略随机种子必须得到同一选择。

宿主拟增加按席位注册的 AI factory 和通用 `runAgentDecision`；这两个名字目前不是现有 API。
Browser 与 Simulation 共用 factory、默认配置和算法身份，Simulation 额外记录训练数据。
重置、加载或更换算法时清空算法临时状态。首版不支持 Promise；未来异步推理增加 requestId、
generation、deadline、cancel 和 late-response 拒绝后再开放，不能直接把 Promise 塞进当前协调器。

### 可信分支服务

新搜索不调用旧 Heuristic 的目标枚举或后继筛选；复用 Production 的 createFork、输入端口与投影。
在可信适配层提供最小服务，算法只拿不透明分支句柄及自身可见结果：

| 拟定能力 | 责任 |
| --- | --- |
| `openRoot()` | 在当前权威边界建立可复现搜索根，隐藏 envelope 和 RNG |
| `expand(node, actionId)` | 从该节点合法集准确匹配并真实提交；返回后继句柄、观察、合法集、状态与执行成本 |
| `release(node)` | 释放分支；搜索结束、失败或超时均由适配层统一回收 |

具体函数名可随最小实现调整，不先建通用插件框架。节点的完整状态、恢复 envelope、
隐藏牌序与真实 RNG 只留在可信层；算法不能从句柄提取它们。
`expand` 的动作只在其节点有效；找不到 actionId 就失败，不能按 family 替换。

节点结果区分 `decision`、`stable`、`terminal`、`information-barrier`、`failed`。
stable 指当前输入的确定性效果已经排空，且没有未解决 Decision；不表示已经完成整回合。
尚有付款或奖励选择时必须展开 Decision；预算不足留下未完成节点，不冒充已兑现收益。
跨到其他玩家 owner 时先停止搜索，初版不替对手作决定。

隐藏抽牌、未揭示外星人与新的随机结果采用信息屏障：初版搜索在屏障处停止，结果遮蔽后才能估值，
不能利用正式隐藏世界中的实际抽牌倒选根动作。屏障之前已确定的收益可以保留，未来部分标未知。
将来若采样未知结果，必须从当前可见信息定义独立假设分布，记录采样版本并检验隐藏世界替换不影响决策。
底层 createFork 本身不等于已经提供这层保证。

### 失败和诊断

规则异常、非法返回、错误 owner、失效版本、非有限估值一律显式失败，保存失败前检查点和诊断。
有合法稳定叶时，预算耗尽可返回当前最佳叶对应的根动作，并标记 incomplete；
没有可评分叶时返回明确失败，不能隐式选择首项或 PASS。

每次真实决策保存：算法与配置身份、观察和合法集摘要、选择及原因、候选覆盖、各候选评分分项、
未评估候选及原因、节点/队列/提交数、分阶段耗时、预算停止原因。
运行身份与完整 checkpoint 单独保存，面向策略的 trace 不包含隐藏状态。

## 三 从基础 AI 到搜索 AI

| 阶段 | 交付内容 | 通过条件 |
| --- | --- | --- |
| 0 接口基线 | 共享 factory 注册、可信观察边界、决策 fixture 读取与记录、算法身份 | 同一 fixture 在 Browser 和 Simulation 选择一致；策略选择阶段不提交正式状态 |
| 1 基础 AI | 不搜索的确定性完成策略，覆盖开局、付款、弃牌、奖励、任务、终局标记及 turn 行动 | 开发种子全部自然终局；无非法动作、重复切换死循环和未处理 family；恢复后后续选择可复现 |
| 2 独立估值 | 纯函数估值和分项输出；完成态与未完成态区分 | 手工可计算的小局面排序正确；得分只记一次；无非有限值；新增输入通过审计 |
| 3 有限预算搜索 | 真实规则展开、统一队列、精确去重、预算及覆盖诊断 | 通过决策反例和下述性能门限后才跑完整局；完整分支与直接执行一致，根状态/RNG/replay 不变 |
| 4 对局评测 | 新协议、冻结基础对手、配对完整局、席位轮换、报告 | 正确性全通过，效果达到事先写定的本轮假设；失败局完整计入，不只挑高分 |
| 5 可选优化 | 计划复用、缓存或学习策略，每次只加一项 | 单独证明收益、失效行为和资源成本；新增能力不能改变公共规则语义 |

基础 AI 的初始选牌和多选决策必须理解选择/取消/确认的正式状态：
按稳定顺序补足未选项，达到要求后确认；不能每次取 legal[0] 反复 toggle。
该策略只负责提供合法、可复现的对局基线，不把选择顺序当作棋力结论。
若当前观察缺少完成策略所需的公开选择状态，先补共享观察与契约测试，不能靠宿主私有状态猜测。

新实现使用独立模块与算法 ID，不在旧 Heuristic 内增加分支。
只新增当前阶段需要的模块；通过阶段验收后再向下一层推进。

## 四 估值与搜索的最小设计

### 估值口径

根和叶均使用同席位可见事实。首版拆成：已兑现分、资源、未来收入、科技能力、手牌与公开任务进度。
每个分项必须说明单位、剩余兑现窗口、受益人及是否已被正式分数计入。
终局直接用正式最终分，未来资源和收入不再加潜力。
不得同时把最终计分总额和其中某项正式奖励重复相加。

先用纯函数与小局面核对资源转换、收入时机和结算完成条件，再决定权重；
旧 expected-score-evaluator 只作行为参考，不直接导入其目标选择和搜索规则。
需要新增观察字段时，先确定规则事实的唯一来源，再运行 `node tools/audit_v_state_inputs.js`。

### 搜索范围和状态等价

初版采用同一根下的有限预算队列，先覆盖不同根动作，再按启发式优先级展开；
条件选择属于正式搜索步骤。主行动前的交易、弃牌角标、移动可以继续到稳定行动结果，
不能只用一步即时加分比较而丢掉准备链。
若完整根覆盖超出预算，记录未评估集合和分配规则，不宣称穷举最优。

状态去重先采用可信层的完整等价：规则状态、working session/Decision、owner、
正式随机状态和序号相同才可合并；路径诊断中的时间戳不属于规则身份。
多条路径保留到各自根动作的归属，不能合并后把一个根的收益算给另一个根。
初期只做精确去重，不做仅凭资源或分数的支配删除。
算法可见观察相同不代表内部状态等价，也不能让隐藏状态键成为算法输入。

准备链先核对当前目标可达性和最低资源需求；只有证明在剩余规则窗口内无法满足时才可剪枝。
无法证明下界时保留并由预算截断，不把启发式低优先级说成不可达。
深度上限和每根叶上限属于截断；beam 是全局队列容量限制，必须单独计数。

### 预算和性能

以下是首版建议值，阶段 3 的单决策 benchmark 通过后随算法配置冻结；不继承旧 30 秒预算：

| 限制 | 首版建议 | 统计口径 |
| --- | --- | --- |
| 全局展开节点 | 1024 | 所有根与所有条件步骤合计，不能每个根重置 |
| 全局规则输入提交 | 2048 | 包含宏步内折叠提交，不能用折叠绕过计算预算 |
| 全局 frontier | 128 | 同时保留的待展开节点，丢弃记 beam 截断 |
| 墙钟搜索期限 | 2000 ms | 含分支复制、规则执行、投影与估值 |
| 端到端决策耗时 | P95 ≤ 1000 ms，最大 ≤ 2500 ms | 固定机器、固定 fixture 集，含入口与诊断开销 |

同步规则宏步不能被墙钟检查中途打断；必须在步前后检查，并分别记录超限宏步和实际最大耗时。
搜索期限是停止展开的软边界，最大耗时是实测验收条件。未达标先 profile，再修改，
不能先加预算或先跑全盘。基准报告同时列 root action 数、成功提交数、fork/规则/观察/估值耗时和峰值队列。

## 五 每次开发的执行顺序

1. **固定问题。** 写一个输入局面、预期选择或预期关系、失败表现和本轮 PASS 条件。
   区分规则接入、候选遗漏、搜索范围、估值、执行与性能问题。
2. **保存反例。** 保存带日期和算法版本的可信 checkpoint、席位观察、legal set、配置和预期。
   从 checkpoint 重建时核对世界与规则版本；策略输入包和隐藏 checkpoint 分开。
3. **只改一层。** 先运行失败反例，再修改对应模块；涉及规则行为时修规则并更新规则版本，
   不能在 AI 里伪造收益或写手工状态补丁。
4. **做必要验证。** 运行相关 `node --check` 与登记的行为测试；搜索变更先跑单决策 benchmark。
   fixture 集同时包含开发反例和未参与调参的回归局面，检查根不变、隐私和 owner。
5. **跑小规模完整局。** 通过前序验证后，使用标准实验入口登记并运行开发集，持续显示进度、保存可续跑检查点。
   快速片段只检查行为和性能，不能替代终局成绩。
6. **进入冻结评测。** 只在候选算法和门槛冻结后使用保留集，报告完整样本和失败原因。
7. **收口。** 核对 diff、文档和结果身份，按仓库约定只提交本轮改动并推送 origin/dev。
   未通过的阶段保留诊断，不把“测试绿”写成“棋力提高”。

单元测试按 `docs/node-testing.md` 登记；保持仓库唯一 full-flow。
Browser 装配、输入或恢复发生变化时执行 Browser smoke。
本流程不要求普通纯函数改动每次跑全量测试或大型对局。

## 六 新评测协议

旧成绩不转成新基线。阶段 1 产出的基础 AI 先冻结版本，建立新的开发集与保留集。
首版建议开发集 8 个种子；保留集 32 个未参与调参种子，每种子轮换候选算法的 4 个席位，
其余 3 席使用同一个冻结基础对手，共 128 局。基础对照组用相同种子和席位配置。
全席 self-play 可作稳定性检查，竞争效果以配对对照为准。

| 类别 | 必须报告 |
| --- | --- |
| 正确性 | 自然终局率、非法动作数、死循环/超步数、异常、超时、终局标记是否结清 |
| 棋力 | 候选席位正式最终分、配对分差、胜率、各席位分布、均值/中位数/P25、分差置信区间 |
| 搜索 | 根覆盖、完成叶比例、各类截断、信息屏障、失败分支与无解决策 |
| 性能 | P50/P95/最大决策耗时、总局时、节点数、成功规则提交数与环境版本 |

正式推广要求评测集全部正常终局且非法动作与死循环为零；性能通过冻结门限。
是否要求涨分由本轮实验假设事先确定；声称棋力改善时须给配对效应和不确定性，
证据不足就保留候选，不能用某个单局最高分代替。
失败局必须列入总样本，未终局分不当作最终分；成功局的分数统计同时报告分母和失败率。
训练、调参、开发集与保留集分离；改动保留集或门槛发布新协议 ID。

## 七 实验身份与工具接入

继续使用 `tools/robot_iterate.js` 登记和运行，复用其去重与续跑能力；先扩展其通用 AI 装配，
不能通过直接运行裸对局脚本绕过去重。新算法接入完成前不执行这些新协议对局。

每条新记录至少绑定：代码提交与实际源码摘要、规则版本、世界指纹、算法 ID/version、
配置和模型 checksum、评测协议、种子、席位、对手身份、预算、运行环境。
共享脏工作树的 HEAD 不代表实际执行代码；正式比较使用已提交且可重建的独立快照。
一次性诊断可记录源码摘要，但不能冒称已提交版本的成绩。

产物继续放入既有 reports/research、reports/iteration 和 seti-saves 体系，文件名带日期或版本，
保存 manifest、checkpoint、确认 replay、决策 trace、汇总报告。
同一算法、实际代码、配置、世界与协议的实验直接复用已有结果；失败重试保留原记录与原因。
快速验证续跑只在实际执行代码、规则、算法和配置一致时进行；更换算法必须新建实验，不能拼接成绩。

## 八 第一批实施任务与完成边界

第一批只完成阶段 0 和阶段 1：

1. 为 Browser 与 Simulation 增加同一套按席位 AI factory 注入，保留原执行与记录链。
2. 建立决策输入 fixture 与独立诊断输出，覆盖不同 Decision owner 和初始多选状态。
3. 实现能正确完成选择和对局的最小基础 AI，关闭新 AI 的计划复用。
4. 把算法身份接入标准实验记录，在开发种子上完成自然终局与 checkpoint 恢复验证。

第一批通过后才实现独立估值与可信搜索适配层。计划复用需比较开关前后的合法性、
信息变化失效和质量/耗时；学习策略需另行确定训练目标、推理延迟及模型版本管理。
旧搜索、估值和实验材料保留原样，仅在确有接口依赖时查阅；不要求先清完旧待办。
