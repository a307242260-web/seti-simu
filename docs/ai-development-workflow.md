# SETI AI 开发流程

设计日期：2026-10-22。目标是建立一套可独立替换算法、稳定复现决策、比较完整终局效果的开发流程。
当前接口依据见 [接口清单](ai-interface-inventory-20261022.md)。本文定义新的开发主线；旧 AI 的待办、
历史成绩和阶段门槛不作为启动条件。现有规则、存档和输入契约继续有效。

首个交付目标是一个覆盖全部决策阶段、能合法结束对局、每步可解释和可重放的基础 AI。
随后分别建设估值、必要分支搜索和对局评测；计划复用与缓存纳入搜索提速主线。
实施进度见 [AI 实施记录](ai-implementation-20261022.md)。下文未标为已实现的能力仍属设计；
硬性要求不是已达标的实测结论。

## 基础验收要求

2026-10-22 用户明确要求：单局游戏不能超过 3 分钟，要快；可复现；完成有必要探索的每一条线。
计划复用和缓存可以作为提速手段。三项要求同时满足，不用涨分抵消超时，也不用少探索换取达标。

整局时间按四席全 AI 的端到端墙钟时间验收，从开始创建对局到终局标记全部结清并写出结果，
包含开局选择、全部席位推理、规则执行、观察、必要诊断和序列化；每局必须 ≤180 秒，
不能只验均值或 P95。Browser 的人为播放等待和人类思考另列，不混入计算基准，也不能据此声称真实交互局必然三分钟结束。
固定测试机器、规则和运行配置，报告冷缓存与热缓存结果；正式速度验收先使用冷缓存完整局，
缓存预热若为运行必需则计入时间。

可复现要求相同规则、算法、配置、初态和策略种子产生相同动作序列与正式结果；
检查点恢复后后缀一致。队列顺序、平分选择、缓存命中和计划复用都不能引入随机的计算次序依赖。
按确定性工作量安排搜索，墙钟只作超时监控，不能让机器负载决定哪个候选成为赢家。

必要探索范围覆盖当前可见信息与决策窗口内所有可能改变选择的行动、准备链和非等价条件选择；
不能只检查每个 family 或每个根动作一次。每条线须有明确结论：完成到定义的比较边界，
或有精确等价、不可达、有效收益上界等排除依据。启发式低分、队列满或时间不足不构成排除证明。
比较边界必须在实现前声明，并用跨步骤反例验证足以支持当前选择；不能缩短到一步来制造覆盖率。
对手 owner 或信息屏障是已声明的能力边界，需单独报告未来未展开范围，不能声称已穷举未来整局。

每次决策保留逐分支去向和汇总：已完成、等价复用、证明剪枝、边界停止、仍待探索。
必要范围内仍有待探索分支即不通过覆盖验收。若尚不能同时做到覆盖和 180 秒，标记未达标，
继续定位瓶颈或改进剪枝、复用，不能隐式接受有损截断。

## 一 采用的技术路线

优先采用纯 JavaScript 决策函数和有界搜索，Browser 与 Simulation 装配同一实现。
这样可以先把规则接入、决策质量和计算成本分别量清楚。
另一条路线是直接训练策略或价值网络，但需要先建立可靠采样、冻结评测和模型推理接口；
放在本流程后期，避免用训练掩盖输入或执行问题。

```text
正式规则 → 席位观察与合法动作 → 共享协调器 → 新 AI 决策函数
                                                │
                          候选排序 → 搜索 → 叶估值
                                      │
                          可信分支服务 → 正式规则隔离分支
                                                │
                                返回 actionId → 协调器正式提交
                                                │
                               replay / checkpoint / 决策诊断
```

AI 只拥有选择。正式合法性、资源扣除、结算、条件 Decision、终局计分归规则；
恢复、执行和记录归宿主。候选排序、搜索调度和估值分别有可替换入口，初期用普通函数实现。

## 二 新 AI 的接入契约

### 决策函数

保留协调器已有的同步最小签名，不先引入新一套 Policy 信封：

```js
const runtime = createAgentDecisionFunction({
  seatId, createAgent: createSearchAgent,
  analysisPortFactory: () => createAnalysisPort({ composition, seatId }),
});
coordinator.registerSeat(seatId, runtime.run);
// factory收到seatId、只读config与惰性analysisPort；decide只收到冻结席位context。
```

最小接入先返回 actionId。搜索接入时可返回经验证的 plan，由协调器复用；新 AI 不读取旧 AI 的计划缓存。
策略只消费已冻结的席位观察与合法 descriptor。sessionDecision 的完整 runtime 对象留在可信边界，
进入算法的数据只取已确认公开的结构化 Decision 信息；不能把整个 session 传进模型。
同一算法版本、输入和策略随机种子必须得到同一选择。

现已接入共享 `createAgentDecisionFunction` 和按席位实例化的 factory，Simulation 提供 `runAgentDecision`。
内置基础 AI 使用 `reset({agentType:"completion"})`；自定义 factory 由
`createSimulationEnv({agentFactory})` 注入。Browser 通过 bootstrap 的同名 factory 参数注入，
页面可用 `?agent=completion` 选择基础 AI。基础实现不搜索，coverage 标记为 not-evaluated。
实验搜索使用同一个`createSearchAgent`：Simulation的`agentType:"search"`与页面`?agent=search`。
其固定预算、完整证据、失败和纯选择续用契约见[共享搜索玩家](ai-search-agent-contract-20261023.md)。
该入口已经接通，复杂场景仍会明确失败，尚不能作为完整对局或180秒验收版本。
Browser 与 Simulation 共用 factory、默认配置和算法身份，Simulation 额外记录训练数据。
重置、加载或更换算法时清空算法临时状态。首版不支持 Promise；未来异步推理增加 requestId、
generation、deadline、cancel 和 late-response 拒绝后再开放，不能直接把 Promise 塞进当前协调器。

### 可信分支服务

新搜索不调用旧 Heuristic 的目标枚举或后继筛选；复用 Production 的 createFork、输入端口与投影。
在可信适配层提供最小服务，算法只拿不透明分支句柄及自身可见结果：

| 拟定能力 | 责任 |
| --- | --- |
| `openRoot()` | 在当前权威边界建立可复现搜索根，隐藏 envelope 和 RNG |
| `expand(node, actionId)` | 从该节点合法集准确匹配并真实提交；返回后继句柄、观察、合法集、状态与执行成本 |
| `release(node)` | 释放分支；搜索结束、失败或超时均由适配层统一回收 |

具体函数名可随最小实现调整，不先建通用插件框架。节点的完整状态、恢复 envelope、
隐藏牌序与真实 RNG 只留在可信层；算法不能从句柄提取它们。
`expand` 的动作只在其节点有效；找不到 actionId 就失败，不能按 family 替换。

节点结果区分 `decision`、`stable`、`terminal`、`information-barrier`、`failed`。
stable 指当前输入的确定性效果已经排空，且没有未解决 Decision；不表示已经完成整回合。
尚有付款或奖励选择时必须展开 Decision；预算不足留下未完成节点，不冒充已兑现收益。
跨到其他玩家 owner 时先停止搜索，初版不替对手作决定。

隐藏抽牌、未揭示外星人与新的随机结果采用信息屏障：初版搜索在屏障处停止，结果遮蔽后才能估值，
不能利用正式隐藏世界中的实际抽牌倒选根动作。屏障之前已确定的收益可以保留，未来部分标未知。
将来若采样未知结果，必须从当前可见信息定义独立假设分布，记录采样版本并检验隐藏世界替换不影响决策。
底层 createFork 本身不等于已经提供这层保证。

PASS预留牌的公开也属于信息屏障：强制弃牌与首个PASS公转之后、预留选择之前停止，
不能利用未来选项倒选PASS之前的行动。实际公开后的新根可按已知合法选项继续；
受限数值等价及真实见证契约见[预留选择证明](ai-pass-reserve-choice-proof-20261023.md)。

### 失败和诊断

规则异常、非法返回、错误 owner、失效版本、非有限估值一律显式失败，保存失败前检查点和诊断。
预算或时间耗尽时记录 incomplete、当前最佳叶和未完成分支，用于诊断，不认作必要探索已完成。
正式验收只接受必要范围已经闭合的决策；没有可评分叶时明确失败，不能隐式选择首项或 PASS。

每次真实决策保存：算法与配置身份、观察和合法集摘要、选择及原因、候选覆盖、各候选评分分项、
未评估候选及原因、节点/队列/提交数、分阶段耗时、预算停止原因。
运行身份与完整 checkpoint 单独保存，面向策略的 trace 不包含隐藏状态。

## 三 从基础 AI 到搜索 AI

| 阶段 | 交付内容 | 通过条件 |
| --- | --- | --- |
| 0 接口基线 | 共享 factory 注册、可信观察边界、决策 fixture 读取与记录、算法身份 | 同一 fixture 在 Browser 和 Simulation 选择一致；策略选择阶段不提交正式状态 |
| 1 基础 AI | 不搜索的确定性完成策略，覆盖开局、付款、弃牌、奖励、任务、终局标记及 turn 行动 | 开发种子全部自然终局；无非法动作、重复切换死循环和未处理 family；恢复后后续选择可复现 |
| 2 独立估值 | 纯函数估值和分项输出；完成态与未完成态区分 | 手工可计算的小局面排序正确；得分只记一次；无非有限值；新增输入通过审计 |
| 3 必要分支搜索与提速 | 真实规则展开、精确去重、证明剪枝、计划复用、缓存和覆盖诊断 | 必要分支全部有结论；单决策基准通过后才跑完整局；分支与直接执行一致，根状态/RNG/replay 不变 |
| 4 对局评测 | 新协议、冻结基础对手、配对完整局、席位轮换、报告 | 每局 ≤180 秒，可复现且必要探索完成；失败局完整计入，不只挑高分 |
| 5 可选学习策略 | 在已有可复现基线与冻结评测上引入学习策略 | 单独证明收益、失效行为和资源成本；不能降低基础验收要求 |

基础 AI 的初始选牌和多选决策必须理解选择/取消/确认的正式状态：
按稳定顺序补足未选项，达到要求后确认；不能每次取 legal[0] 反复 toggle。
该策略只负责提供合法、可复现的对局基线，不把选择顺序当作棋力结论。
若当前观察缺少完成策略所需的公开选择状态，先补共享观察与契约测试，不能靠宿主私有状态猜测。

新实现使用独立模块与算法 ID，不在旧 Heuristic 内增加分支。
只新增当前阶段需要的模块；通过阶段验收后再向下一层推进。

## 四 估值与搜索的最小设计

### 估值口径

根和叶均使用同席位可见事实。首版拆成：已兑现分、资源、未来收入、科技能力、手牌与公开任务进度。
每个分项必须说明单位、剩余兑现窗口、受益人及是否已被正式分数计入。
终局直接用正式最终分，未来资源和收入不再加潜力。
不得同时把最终计分总额和其中某项正式奖励重复相加。

先用纯函数与小局面核对资源转换、收入时机和结算完成条件，再决定权重；
旧 expected-score-evaluator 只作行为参考，不直接导入其目标选择和搜索规则。
需要新增观察字段时，先确定规则事实的唯一来源，再运行 `node tools/audit_v_state_inputs.js`。

### 搜索范围和状态等价

初版采用同一根下的统一队列，先覆盖不同根动作，再按确定性优先级展开；
条件选择属于正式搜索步骤。主行动前的交易、弃牌角标、移动可以继续到稳定行动结果，
不能只用一步即时加分比较而丢掉准备链。
启发式仅影响先后顺序。若必要分支超出预算，保存未评估集合并判未达标，不能删除后宣称完成。

状态去重先采用可信层的向前执行等价：规则状态、working session/Decision、owner、
规则随机状态和有规则含义的实体序号相同才可合并；路径诊断中的时间戳、journal/undo 历史和
authority 版本不属于向前规则身份。剩余 Effect/Group 引用允许保留引用关系的编号规范化，
不能删除剩余队列或重排语义数组。当前弃牌堆在向前分析中按实体 ID 集合比较，
依据见[弃牌堆顺序等价证明](ai-discard-order-proof-20261022.md)。
[玩家数据标记](ai-data-token-equivalence-20261022.md)忽略编号、显示序号与池展示位置，
已放标记按真实目标位比较；其他实体和语义数组仍保留原身份与顺序。
此契约不覆盖 undo/abort、UI 历史顺序或读取日志的自定义规则。
多条路径保留到各自根动作的归属，不能合并后把一个根的收益算给另一个根。
不做仅凭资源或分数的支配删除；支配或收益上界剪枝必须说明成立条件并给反例测试。
当前显式可选的[主行动后钱电支配](ai-resource-dominance-proof-20261022.md)仅适用于受限的赫利昂窗口，
不能直接推广到主行动前、保留卡或外星人状态。
另有逐张核对五种手牌后的[首个主行动证明](ai-opening-resource-proof-20261022.md)，
要求无本席探测器、无科技且所有席位保留区为空；逐根分数标明已取得下界，不冒充逐根完整比较。
搜索v21另有[已知模型钱电证明](ai-known-card-money-proof-20261023.md)，在精确状态身份下按
DSL结构审核可达手牌、保留/停放牌与公司换牌；未知或非单调模型不支配。
它保留原两份证明的限制，不能因为局部剪枝有效就宣称复杂主行动已经闭合。
另有[取牌交易信息边界上界](ai-card-trade-bound-proof-20261022.md)，只在可信规则条件满足且
已有真实边界叶严格胜过上界时省略子树；不把一个低即时值当作整条准备链的收益上界。
搜索v22的取牌界v4按交易局部事件闭包接受标准保留牌和就绪任务；不推进回合、不自动兑付任务，
仅在所有剩余交易出口到信息边界的值都有依据时省略。它不扩大其他阶段的保留牌证明。
同一证明的 `cardChoiceEquivalence` 在交易子路径中仅在所有选牌都用一步到达相同数值的信息边界时
保留最小 actionId，并执行真实见证核对预测值。其他出口标明未执行及证明归属；
搜索v23还在此开关下使用[主行动后角标行为等价](ai-post-main-corner-choice-proof-20261023.md)，
以收入/角标用途及封闭后续路径证明等长等值；它不合并状态，不扩大主行动前或付款集合的等价范围。
这不是状态等价，不能越过信息屏障。全部弃牌支付集合仍完整求值，供后续点击复用。
算法可见观察相同不代表内部状态等价，也不能让隐藏状态键成为算法输入。

`postMainPruning` 只对[已证明的主行动后范围](ai-post-main-plan-proof-20261022.md)
保留数据放置和结束回合，省略严格无收益的交易与角标。只接受冻结的默认 V；
收入4号位、金标阈值、揭示资格、公司能力和非普通探测器等不满足前提时继续原搜索。
普通探测器移动仅在证明每点费用至少1个默认V、每次到达收益至多0.5个V且无额外观察奖励时省略；
主行动前的移动仍保留，不能把当前窗口内的净损失推广为路线没有长期价值。
这是保持局部最大值和最短输入的路径证明，不是按即时低分删分支。
省略记录须引用保留图的实际完成叶；图未闭合不返回动作，省略根不伪造值或边。
搜索v24的主行动后证明按不活动闭包检查保留牌：尚未满足且不会变化的踪迹/扇区任务、
已消耗或只监听不可达事件的触发器，以及窗口内不变的终局公式。历史待结算事件必须排除。
对手标准保留牌保留身份且不在本owner窗口结算；本席尚可触发的B44/B71访问奖励仍保留，
有本席探测器时不能因当前尚未到达而视为不可达。取牌界继续使用其独立的交易事件闭包。

准备链先核对当前目标可达性和最低资源需求；只有证明在剩余规则窗口内无法满足时才可剪枝。
无法证明下界时保留，不把启发式低优先级说成不可达。
深度上限、每根叶上限和 beam 丢弃均属于有损截断，不能通过必要探索验收。
内存有界时可分批处理或保存待处理队列；队列暂未驻留不等于已经完成或已被剪枝。

### 计划复用与缓存

计划复用和缓存是达到整局 180 秒的主线能力，与搜索一起开发，无需等到最后才加。
当前[分支状态复用](ai-fork-state-reuse-20261023.md)按完整字节共享冻结committed根，
并在受信任隔离store中按对象身份缓存canonical序列化；工作副本与Session不共享。
先建立不开复用和缓存的正确性对照，再分别启用以衡量计算节省。

计划只保存真实搜索得到的步骤与依赖；每步检查当前 owner、合法集、可见信息变化、目标机会和依赖。
命中后将计划中的语义步骤匹配到当前正式 descriptor，再提交；失效立即重新搜索，不能执行旧版本信封。
若要跳过整个重新决策，依赖证据还须证明其他必要竞争线的比较结论仍成立；
只证明下一步依然合法，不足以证明继续该计划仍可替代必要探索。

缓存分为规则事实/投影、精确等价分支结果、估值与已完成搜索证据，按实际需要实现。
缓存键须覆盖影响结果的规则与算法版本、配置、viewer/owner、完整适用状态及信息边界；
不能仅按 stateVersion、资源摘要或 action family 跨分支复用，也不能把隐藏状态键暴露给策略。
缓存的搜索结果必须带范围与完成证据，不能把一次 incomplete 命中视为全部覆盖。
不同根共享同一执行结果时仍保留各自行动来源。

缓存有明确容量和确定性淘汰顺序。缓存命中、关闭缓存、淘汰后重算的选择与结果应一致；
计划复用在同一适用证据下也应保持相同选择。分别记录命中率、节省的提交数/耗时、失效原因和内存，
并验证不同席位隔离、恢复与版本切换。缓存文件如参与运行，绑定内容指纹，不能让未登记旧缓存影响复现。

搜索v20实现[已闭合窗口最优前缀复用](ai-plan-prefix-reuse-proof-20261023.md)：稳定的回合假设种子，
完整规则身份、RNG与合法信封绑定，按原完整图的最优值、距离及边界见证复用单输入前缀。
首次求解仍须闭合；宏内部未建图节点、信息公开和依赖变化不沿用旧结论。证据缓存最多32项，
容量限制只导致重算，不截断必要探索。当前模型对根知识遮蔽的V不变性是明确前提，新增特征须重审。

### 预算和性能

总约束为每局 ≤180 秒。先测不搜索基础 AI 的规则、投影、记录总耗时，再把剩余时间分配给搜索，
并保留结算与波动余量。单决策工作额度由固定版本的确定性规则分配，并报告整局累计成本；
不能给每个决策 1 至 2 秒后推断整局达标。尚无单步成本和决策数证据，不预定通用毫秒/节点额度。

| 限制 | 确定方式 | 统计口径 |
| --- | --- | --- |
| 整局时间 | 用户硬上限 180 秒 | 初始化至终局结果完成，所有席位合计 |
| 单决策节点与规则提交额度 | 由单决策 profiling 和整局成本模型冻结 | 所有根、条件步骤与折叠提交合计，不能每根重置 |
| 全局待处理队列内存 | 按机器内存与单节点大小冻结 | 分批/持久化，不能无证据丢弃必要分支 |
| 搜索深度和比较边界 | 根据准备链与决策窗口定义并验证 | 未完成义务独立保留，不用深度截断伪装完成 |
| 单步性能门限 | 从整局预算反推，并在单决策基准测量 | 报 P50/P95/最大值及昂贵宏步，不用均值掩盖超限 |

同步规则宏步不能被墙钟检查中途打断；必须在步前后检查，并分别记录超限宏步和实际最大耗时。
超时监控不能中断后直接宣告覆盖完成；超时保存现场并判失败。未达标先 profile，再修改，
不能先放宽 180 秒要求或先跑全盘。基准报告同时列必要分支数、各分支去向、成功提交数、
fork/规则/观察/估值耗时、缓存与计划收益及峰值队列。

## 五 每次开发的执行顺序

1. **固定问题。** 写一个输入局面、预期选择或预期关系、失败表现和本轮 PASS 条件。
   区分规则接入、候选遗漏、搜索范围、估值、执行与性能问题。
2. **保存反例。** 保存带日期和算法版本的可信 checkpoint、席位观察、legal set、配置和预期。
   从 checkpoint 重建时核对世界与规则版本；策略输入包和隐藏 checkpoint 分开。
3. **只改一层。** 先运行失败反例，再修改对应模块；涉及规则行为时修规则并更新规则版本，
   不能在 AI 里伪造收益或写手工状态补丁。
4. **做必要验证。** 运行相关 `node --check` 与登记的行为测试；搜索变更先跑单决策 benchmark。
   fixture 集同时包含开发反例和未参与调参的回归局面，检查根不变、隐私和 owner。
5. **跑小规模完整局。** 通过前序验证后，使用标准实验入口登记并运行开发集，持续显示进度、保存可续跑检查点。
   快速片段只检查行为和性能，不能替代终局成绩。
6. **进入冻结评测。** 只在候选算法和门槛冻结后使用保留集，报告完整样本和失败原因。
7. **收口。** 核对 diff、文档和结果身份，按仓库约定只提交本轮改动并推送 origin/dev。
   未通过的阶段保留诊断，不把“测试绿”写成“棋力提高”。

单元测试按 `docs/node-testing.md` 登记；保持仓库唯一 full-flow。
Browser 装配、输入或恢复发生变化时执行 Browser smoke。
本流程不要求普通纯函数改动每次跑全量测试或大型对局。

## 六 新评测协议

旧成绩不转成新基线。阶段 1 产出的基础 AI 先冻结版本，建立新的开发集与保留集。
首版建议开发集 8 个种子；保留集 32 个未参与调参种子，每种子轮换候选算法的 4 个席位，
其余 3 席使用同一个冻结基础对手，共 128 局。基础对照组用相同种子和席位配置。
全席 self-play 可作稳定性检查，竞争效果以配对对照为准。

| 类别 | 必须报告 |
| --- | --- |
| 正确性 | 自然终局率、非法动作数、死循环/超步数、异常、超时、终局标记是否结清、动作序列及恢复后缀复现 |
| 棋力 | 候选席位正式最终分、配对分差、胜率、各席位分布、均值/中位数/P25、分差置信区间 |
| 搜索 | 必要分支逐线去向、完成与证明剪枝、信息边界、未完成义务、失败分支与无解决策 |
| 性能 | 每局总耗时及最大值、超过 180 秒局数、P50/P95/最大决策耗时、提交数、缓存/计划收益与环境版本 |

正式推广要求评测集全部正常终局且非法动作与死循环为零，每局 ≤180 秒，
必要探索未完成数为零，可复现验证通过；计划/缓存开关对照不能改变应有决策结果。
是否要求涨分由本轮实验假设事先确定；声称棋力改善时须给配对效应和不确定性，
证据不足就保留候选，不能用某个单局最高分代替。
失败局必须列入总样本，未终局分不当作最终分；成功局的分数统计同时报告分母和失败率。
训练、调参、开发集与保留集分离；改动保留集或门槛发布新协议 ID。

## 七 实验身份与工具接入

继续使用 `tools/robot_iterate.js` 登记和运行，复用其去重与续跑能力；先扩展其通用 AI 装配，
不能通过直接运行裸对局脚本绕过去重。新算法接入完成前不执行这些新协议对局。

每条新记录至少绑定：代码提交与实际源码摘要、规则版本、世界指纹、算法 ID/version、
配置和模型 checksum、评测协议、种子、席位、对手身份、预算、运行环境。
共享脏工作树的 HEAD 不代表实际执行代码；正式比较使用已提交且可重建的独立快照。
一次性诊断可记录源码摘要，但不能冒称已提交版本的成绩。

产物继续放入既有 reports/research、reports/iteration 和 seti-saves 体系，文件名带日期或版本，
保存 manifest、checkpoint、确认 replay、决策 trace、汇总报告。
同一算法、实际代码、配置、世界与协议的实验直接复用已有结果；失败重试保留原记录与原因。
快速验证续跑只在实际执行代码、规则、算法和配置一致时进行；更换算法必须新建实验，不能拼接成绩。

## 八 第一批实施任务与完成边界

第一批只完成阶段 0 和阶段 1：

1. 为 Browser 与 Simulation 增加同一套按席位 AI factory 注入，保留原执行与记录链。
2. 建立决策输入 fixture 与独立诊断输出，覆盖不同 Decision owner 和初始多选状态。
3. 实现能正确完成选择和对局的最小基础 AI，关闭新 AI 的计划复用。
4. 把算法身份接入标准实验记录，在开发种子上完成自然终局与 checkpoint 恢复验证，并测量整局基础耗时。

第一批基础 AI 只验收接入和对局完成，不代表已完成用户要求的必要搜索。
第一批通过后实现独立估值与可信搜索适配层，同时接入计划复用和缓存以满足整局速度要求。
学习策略需另行确定训练目标、推理延迟及模型版本管理。
旧搜索、估值和实验材料保留原样，仅在确有接口依赖时查阅；不要求先清完旧待办。
